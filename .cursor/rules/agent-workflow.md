# Правила для работы с агентами и workflow-ролями

Эти правила определяют, как работать с агентами-специалистами и workflow-ролями в проекте.

## Workflow-роли

Workflow-роли находятся в `ai/roles/` и определяют этапы разработки:

- **plan** — планирование: discovery + plan в одном этапе
- **design** — дизайн: design-first + архитектура
- **build** — реализация: tests-red + implement + tests-green
- **release** — релиз: gate + acceptance

## Агенты-специалисты

Агенты-специалисты находятся в `ai/agents/` и используются для конкретных задач:

- **Product Lead** — управляет продуктом, определяет проблему, outcome, приоритеты
- **Designer** — UX + BA, строит journey map, требования, прототипы
- **Analyst** — метрики, воронки, аналитика, эксперименты
- **Engineer** — техническая реализация, feasibility, архитектура, код
- **Delivery** — план релиза, координация, зависимости, риски
- **Compliance** — комплаенс, безопасность, приватность

## Как использовать

### Workflow-роли

1. В чате напиши: `FP=FP6 mode=plan` (или другой FP и mode: design, build, release)
2. Агент откроет `ai/roles/<mode>.md` и `AGENTS.md`
3. Агент действует строго по инструкции роли и правилам из `AGENTS.md`

### Агенты-специалисты

1. Используй универсальный шаблон запроса (см. `ai/agents/README.md`)
2. Подключи нужные файлы в контекст
3. Агент вернёт артефакты, а не "разговор"

## Оркестрация

Типовой цикл:

1. **Product Lead** получает задачу, определяет scope и outcome
2. Ты по очереди вызываешь специалистов (Designer, Analyst, Engineer, Delivery, Compliance) и собираешь их выходы
3. **Product Lead** собирает всё в единый пакет артефактов + backlog

## Связь с документацией

Все workflow-роли работают с:
- **Feature Pack файлы:** `docs/fps/FP<N>.md` — единый файл со всей информацией о FP
- **Общие документы:** `docs/core/` — REQUIREMENTS.md, API.yaml, MODEL.sql, UX_MAP.md, TESTS.md, QNA_DECISIONS.md, WORKPLAN.yaml

## Аудит-роли

Аудит-роли находятся в `ai/roles/audit/`:
- **analyst** — фактологический анализ (что реально сделано)
- **inspector** — аудит фактической реализации кода
- **supervisor** — принятие решений на основе анализа, сокращение scope
