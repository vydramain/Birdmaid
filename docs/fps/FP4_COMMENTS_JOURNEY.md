## User Roles & Permissions

### Гость (Unauthenticated Visitor)
- ✅ Может просматривать комментарии
- ❌ Не может оставлять комментарии
- 🔄 Видит призыв к логину

### Участник (Authenticated User)
- ✅ Может просматривать комментарии
- ✅ Может оставлять комментарии
- ✅ Видит свой login в комментариях

### Организатор (Super Admin)
- ✅ Все возможности участника
- ⚠️ Может модерировать комментарии (будущая функция)

## Use Cases

### Main Flow: Просмотр комментариев

1. User открывает страницу игры
2. Система загружает игру и комментарии параллельно
3. User видит секцию "Comments" ниже описания игры
4. Если комментариев нет → показывается "No comments yet."
5. Если комментарии есть → показывается список с userLogin, text, createdAt

**Alternate Flows:**
- Комментарии загружаются с задержкой → показывается loading state
- Ошибка загрузки → комментарии не отображаются (graceful degradation)

**Error Flows:**
- API недоступен → комментарии не загружаются, но страница игры работает

---

### Main Flow: Оставление комментария (Authenticated)

1. User (authenticated) открывает страницу игры
2. User видит форму комментария (textarea + кнопка)
3. User вводит текст комментария
4. User нажимает "Post Comment"
5. Система валидирует: текст не пустой, пользователь авторизован
6. Система отправляет POST /games/{id}/comments
7. Комментарий сохраняется в БД
8. UI обновляется: комментарий появляется в списке, textarea очищается

**Alternate Flows:**
- Текст пустой → кнопка disabled или валидация
- Пользователь не авторизован → показывается призыв к логину

**Error Flows:**
- Ошибка сети → показывается error message
- Токен истек → перенаправление на логин
- Игра не существует → 404 error

---

### Main Flow: Оставление комментария (Guest)

1. User (guest) открывает страницу игры
2. User видит комментарии других пользователей
3. User видит сообщение "Login to post comments" с ссылкой
4. User кликает на ссылку
5. Открывается модальное окно логина (Windows 95 styled)
6. User логинится
7. User возвращается на страницу игры
8. Теперь видит форму комментария

**Alternate Flows:**
- User регистрируется вместо логина → тот же flow
- User закрывает модальное окно → остается на странице игры

**Error Flows:**
- Модальное окно не открывается → перенаправление на страницу логина

## Business Rules

1. **Видимость комментариев:**
   - Комментарии видны всем пользователям (гости и авторизованные)
   - Комментарии показываются только для опубликованных игр (status: "published")

2. **Создание комментариев:**
   - Только авторизованные пользователи могут оставлять комментарии
   - Комментарий должен содержать текст (не пустой, после trim)
   - Комментарий привязывается к игре и пользователю

3. **Отображение комментариев:**
   - Комментарии сортируются по времени создания (старые → новые)
   - Показывается userLogin (не email), текст, дата/время создания
   - Нет редактирования/удаления комментариев (в FP4)

4. **Валидация:**
   - Минимальная длина: 1 символ (после trim)
   - Максимальная длина: не ограничена (можно добавить в будущем)
   - Текст не должен содержать только пробелы

## UI States

### GamePage → Comments Section

**Loading State:**
- Показывается спиннер или skeleton loader
- Комментарии загружаются параллельно с игрой

**Empty State:**
- Показывается сообщение "No comments yet."
- Для авторизованных: показывается форма комментария
- Для гостей: показывается призыв к логину

**Success State (with comments):**
- Список комментариев отображается
- Каждый комментарий: userLogin (жирный), text, createdAt (серый, маленький шрифт)
- Разделители между комментариями (border-bottom)
- Для авторизованных: форма комментария внизу

**Error State:**
- Комментарии не загружаются (graceful degradation)
- Страница игры работает нормально
- Можно попробовать обновить страницу

**Posting State:**
- Кнопка "Post Comment" disabled
- Показывается спиннер (опционально)
- Текст в textarea заблокирован

**Post Success State:**
- Комментарий появляется в списке
- Textarea очищается
- Кнопка снова enabled

**Post Error State:**
- Показывается error message (Windows 95 styled modal)
- Текст в textarea сохраняется
- Можно попробовать отправить снова

## UX Risks

### Confusion Points

1. **Неочевидное расположение комментариев:**
   - Риск: Пользователь не видит комментарии, если не прокрутит вниз
   - Митигация: Добавить якорную ссылку "Комментарии" в навигации или сделать секцию более заметной

2. **Отсутствие обратной связи при отправке:**
   - Риск: Пользователь не знает, отправлен ли комментарий
   - Митигация: Оптимистичное обновление UI + disabled состояние кнопки

3. **Нет индикации загрузки:**
   - Риск: Пользователь не понимает, загружаются ли комментарии
   - Митигация: Skeleton loader или спиннер

### Friction Points

1. **Переход на страницу логина для гостей:**
   - Риск: Пользователь теряет контекст (страницу игры)
   - Митигация: Модальное окно логина (уже реализовано в FP4)

2. **Нет возможности редактировать комментарий:**
   - Риск: Пользователь сделал опечатку, не может исправить
   - Митигация: Добавить редактирование в будущем FP (опционально)

3. **Нет пагинации:**
   - Риск: При большом количестве комментариев страница становится длинной
   - Митигация: Добавить "Показать больше" или бесконечный скролл

### Error-Prone Steps

1. **Отправка пустого комментария:**
   - Риск: Пользователь случайно отправляет пустой комментарий
   - Митигация: Валидация на фронте (disabled кнопка) + валидация на бэке

2. **Отправка комментария без авторизации:**
   - Риск: Пользователь пытается отправить комментарий, но не авторизован
   - Митигация: Форма комментария скрыта для гостей, показывается призыв к логину

3. **Дублирование комментариев:**
   - Риск: Пользователь дважды кликает на кнопку, отправляет два одинаковых комментария
   - Митигация: Disabled состояние кнопки после клика + debounce

## Opportunities for Improvement

1. **Оптимистичное обновление UI:**
   - Сразу показывать комментарий в списке после отправки
   - Обновлять реальными данными после ответа от сервера

2. **Авто-сохранение черновика:**
   - Сохранять текст комментария в localStorage
   - Восстанавливать при возврате на страницу

3. **Уведомления:**
   - Уведомлять автора игры о новых комментариях (будущая функция)

4. **Модерация:**
   - Возможность удалять комментарии (для Super Admin)
   - Возможность редактировать свои комментарии

5. **Ответы на комментарии:**
   - Вложенные комментарии (threads) - будущая функция

6. **Реакции:**
   - Лайки/дизлайки на комментарии - будущая функция

7. **Фильтрация:**
   - Сортировка по дате (новые/старые)
   - Поиск по тексту комментария

## Touchpoints Details

### Comment Card Component

**Визуальная структура:**
```
┌─────────────────────────────────────┐
│ userLogin (жирный, 12px)            │
│ text (обычный, 13px, margin-top)    │
│ createdAt (серый, 11px, margin-top) │
└─────────────────────────────────────┘
```

**Стилизация:**
- Windows 95 styled (использует существующие компоненты)
- Разделитель между комментариями: `border-bottom: 1px solid var(--win-gray-dark)`
- Отступы: `margin-bottom: 12px, padding-bottom: 12px`

### Comment Form Component

**Визуальная структура:**
```
┌─────────────────────────────────────┐
│ Win95Textarea (placeholder:         │
│ "Write a comment...")                │
│                                      │
│ Win95Button "Post Comment"          │
└─────────────────────────────────────┘
```

**Состояния:**
- Default: textarea пустой, кнопка enabled
- Typing: textarea заполняется, кнопка enabled (если текст не пустой)
- Posting: textarea disabled, кнопка disabled + спиннер
- Success: textarea очищен, кнопка enabled
- Error: textarea сохраняет текст, показывается error modal

## Metrics

### Success Metrics

- **North Star:** Number of comments posted per game
- **Supporting:**
  - Number of users who post comments
  - Average comments per user
  - Comments per published game
  - Time to first comment (от открытия игры до первого комментария)

### Events

- `comment_viewed` — когда пользователь просматривает секцию комментариев
- `comment_posted` — когда пользователь отправляет комментарий
- `comment_form_opened` — когда авторизованный пользователь видит форму комментария
- `login_prompt_clicked` — когда гость кликает на ссылку "Login to post comments"
